## Auto-decision D1 (AFK grant): delete `printSlots()`, keep the hifi oracle

Row 140 offers "delete both, or re-derive from `PRINT_LAYOUTS`". Taking the
third path, which is what the row is really asking for:

- **Delete `printSlots()` from `index.html`.** `index.html` IS the shipped
  artifact - GitHub Pages serves the committed bytes - so dead code there is
  shipped weight, and a dead function with a green geometry test beside it is
  an invitation to wire it up.
- **Keep the agreement with `hifi.slots()`, and move it onto the code that
  actually ships.** Derive the slot positions in Python from the CSS
  `printGridCSS()` emits plus the flex centring rule, and compare THOSE to
  `hifi.slots()`. That is the check the row's AC-B3 headline always claimed to
  be making.

**What the derivation can and cannot reach (eng review, 2026-09-22).** The
derivation is exact for `wide`/`letter` and ONLY there. `.printsheet`'s layout
box is `cols*CW + (cols-1)*gx` by `rows*CH + (rows-1)*gy` = 557.2 x 760.4pt;
`display:flex; align-items:center; justify-content:center` centres that box in
`.printpage`, whose width is the page box's and whose height is
`max(100%, min-height)`. Substituting the page box 612 x 792 gives
x0 = 27.4, y0 = 15.8 - `hifi.slots()` exactly. But `index.html:774-779` says in
so many words that the page area is "the one number we are never allowed to
assume", and it is wrong precisely on the platform `narrow` exists for. So:

- **No absolute narrow slots.** The narrow sheet is selected only on platforms
  that ignore `@page`, where the page box is unknown, so its position on paper
  is not derivable from the emitted text at any accuracy. `hifi` has no narrow
  oracle either - `index.html:4144-4147` states that outright - so there is
  nothing to compare absolute narrow coordinates TO.
- **`paper` is not a slot input.** The only paper-dependent thing
  `printGridCSS` emits is `@page{size:...}`; `PRINT_GEOM` carries no A4 page
  box. `css_slots` therefore takes `name` only, and the wide comparison is
  Letter by construction.
- **Narrow gets an internal-consistency check instead**, over the emitted text:
  gaps are `0pt`, the grid is 3 x 2, `transform:rotate(-90deg)` is present, the
  rotated footprint is 494.4 x 532.8pt, and `min-height` equals the ROTATED
  extent (532.8pt), not the unrotated 494.4pt. Where the narrow sheet actually
  lands on paper is already checked end-to-end by the printToPDF oracle at
  `tests/e2e.test.js:1287-1317` (top >= 8pt, |top-bottom| <= 2, |left-right| <= 2).
  That oracle, not a derivation, is the narrow placement evidence.

Rejected: re-deriving `printSlots()` from `PRINT_LAYOUTS` keeps a dead
function in the shipped file and buys nothing the CSS derivation does not.
Rejected: deleting the tests with the function, which would drop the only
cross-renderer geometry check the browser sheet has.
