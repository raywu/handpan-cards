### 2.2 Wrong-but-valid (reported separately, as O6 requires)

Both are NEEDS_INPUT cases that tier 0 returns as REVIEW. The only guard is the NO_OCTAVE CONFIRM tick, which is far too weak for a wrong pan.

1. **yatao-c-ashakiran-15.** Span: `Top Notes: C - F, G, A, B, C, D, E, G` / `Bottom Notes: D, E, F, A, B, C`.
   - Tier 0 gives `(C3) F3 G3 A3 B3 C4 D4 E4 G4 [D5] [E5] [F5] [A5] [B5] [C6]`. It chains the octaveless bottoms upward after the top, so they come out an octave or more too high.
   - The truth is not recoverable from the text.
   - **Fix (T0+, required before any tier ships):** an octaveless bottom list gets a BLOCK, `BOTTOM_NO_OCTAVE`. Bottom notes are never chained from the top.
2. **boullard-battiloro-celtic-contradictory.** Span: `D A C D E F G A C` then `Notes : D A C D E F G A C D`. That is 9 against 10 notes.
   - Tier 0 takes the labelled 10-note line and ignores the unlabelled 9-note line above it.
   - **Fix (T0+):** the after-list scan already blocks a later note run. Extend it to an earlier run of five or more note tokens that disagrees with the chosen list (BLOCK `CONFLICTING_LIST`).

One more case is a source error, not an importer error. thomann-startone-d-kurd-octaveless is `D / A, B, C, …`: the shop prints B where the Kurd has Bb. Tier 0 reproduces the text exactly, which is correct behaviour, but the user gets a wrong pan.

No tier can catch this without inventing a note, and inventing notes is forbidden. The plan's answer is the scale-name cross-check in Open Question Q4: an INFO line when the name says Kurd and the set disagrees. It writes nothing.

**Pick: Cloudflare Workers, on Free at launch (owner decision D-C).** Whether 10 ms of CPU is enough to parse a 2.4 MB page is UNVERIFIED; time spent waiting on a fetch is not CPU. Phase 2c measures it. Go to Paid ($5) only if the CPU limit is hit, and only knowing that Paid has no hard spend cap (4.6).

SSRF facts:

- `global_fetch_strictly_public` exists (developers.cloudflare.com/workers/configuration/compatibility-flags/). It is **not** private-IP protection (devops fix 12). It makes `fetch()` to a hostname on one of the account's own zones go out over the public internet, rather than straight to that zone's origin. The plan sets it so the worker cannot reach an origin behind the owner's zones by that shortcut.
- The SSRF control is the worker's own guards: IP literals and private host names refused, and every redirect hop re-checked (4.4).
- `allow_custom_ports` is on by default there, so the worker must check the port itself.
- Whether Workers refuse private-IP targets or resist DNS rebinding is **UNVERIFIED**. One community report of an exception on an IP-literal hostname exists (community.cloudflare.com/t/exception-when-fetching-url-with-ip-hostname-in-workers/595868). The worker therefore refuses IP literals itself, whatever the platform does.

Abuse control (O11):

- The Rate Limiting binding allows only 10 s or 60 s periods, and its counters are per location. The docs advise against keying on IP (developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/). Its pricing stays **UNVERIFIED** (devops fix 14); L2 must not assume it is free.
- KV is eventually consistent (developers.cloudflare.com/kv/concepts/how-kv-works/), so it cannot hold a budget counter.
- **Durable Objects with the SQLite storage backend are available on Workers Free** (owner decision D-C; developers.cloudflare.com/durable-objects/platform/pricing/, not re-read for this revision). The first revision's "Durable Objects need Paid" was wrong for SQLite-backed objects. Their Free daily allowances are UNVERIFIED here. The plan uses one as the daily budget counter (4.4). On Paid: 1M requests included, then $0.15/M (developers.cloudflare.com/workers/platform/pricing/).
- **Free limits are account-wide** (owner decision D-C).
  - The 100,000 requests a day are shared by every Worker on the account. Past them, every Worker answers Error 1027 until the daily reset.
  - A Free Worker also has a burst limit of 1,000 requests a minute (developers.cloudflare.com/workers/platform/limits/).

## 4. Architecture

### 4.1 Request flow

```
  Add sheet (index.html, app block)                 worker/ (Cloudflare Worker)
  ---------------------------------                 ---------------------------
  [paste box] --IMPORT--> interpret(text)  (local, no network, as today)
                               |
                               v
                         preview + flags --USE (O9)--> #scale-box
                               ^
  [URL field] --READ LINK--> POST /v1/read {url} ----> guards (4.4) -> fetch
     (explicit tap, O4)        |                       shopify .json | JSON-LD | text window
                               | <---- {text, source, finalUrl, truncated}
                               v
                     interpret(text)  (local, tier 0 / T0+)
                               |
              REVIEW? -- yes --> preview (as above)
                 | no
                 v
     the existing INSUFFICIENT or BLOCK line; the text stays in the paste box to edit
```

Any text over 2,000 characters, pasted or fetched, is narrowed to its densest-pitch window inside `interpret` before it is read (L1, CEO fix 16). A shorter paste reads exactly as today.

The worker is never in the path of a paste. If the worker call fails, the app keeps the text it has, shows the error line, and paste import still works.

### 4.2 API contract

`POST /v1/read`. Body `{"url": "<http(s) URL>"}`. Response 200:

```
{"text": "...", "source": "shopify-json" | "json-ld" | "html", "finalUrl": "...", "bytes": 123, "truncated": false}
```

- `text` is at most 60,000 characters. For `html` it is the window around the densest pitch run, at most 8,000 characters.
- **The NO_TEXT rule (CEO fix 15).** The worker answers 422 NO_TEXT unless the text it would return holds at least 5 pitch tokens. This applies on every source path: the Shopify `.json` body, a JSON-LD `description` and the HTML window. It never returns a page of menus.

**CORS (eng fix 4).**

- `OPTIONS /v1/read` answers **204**, with these headers:
  - `Access-Control-Allow-Methods: POST`
  - `Access-Control-Allow-Headers: Content-Type`
  - `Access-Control-Max-Age: 86400`
- `Access-Control-Allow-Origin` echoes the request's `Origin` only when it is one of the two allow-listed origins (4.4), and is sent with `Vary: Origin`. It is **never `*`**.
- A disallowed or missing Origin gets no `Access-Control-Allow-Origin` and a 403 BLOCKED_ORIGIN body.
- L2 test: a disallowed Origin gets no `Access-Control-Allow-Origin`, on OPTIONS and on POST.

| Code | HTTP | App behaviour | Import flag, or the test that proves the row |
|---|---|---|---|
| BAD_URL | 400 | "That is not a web link." Paste stays usable | none (no result) |
| BLOCKED_HOST | 403 | "That address cannot be read." | none |
| BLOCKED_ORIGIN | 403 | The browser hides it behind CORS, so the app sees the `TypeError` row below | none; L2 CORS test |
| TOO_LARGE | 413 | "That page is too large. Paste the notes instead." | none |
| NOT_HTML | 415 | same wording, "not a web page" | none |
| NO_TEXT | 422 | "No notes found on that page. Paste the notes instead." | none; the 5-token rule above |
| RATE_LIMITED | 429 | "Too many imports. Try again in a minute." | none |
| FETCH_FAILED, UPSTREAM_BLOCKED | 502 | "That site did not answer. Paste the notes instead." | none |
| PAUSED | 503 | "Import from links is paused. Paste the notes instead." | none |
| BUDGET_SPENT | 503 | "Import from links has reached today's limit. Paste the notes instead." | none; the daily counter (4.4) |
| TIMEOUT | 504 | same as 502 | none |
| (app) the fetch rejects with a `TypeError`: offline, DNS failure, a CORS refusal | | "Could not reach the link reader. Paste the notes instead." | none; L3 test with a fake `fetch` that rejects (eng fix 4) |
| (app) any other non-2xx status, or a body that is not JSON, such as Cloudflare's own Error 1027 and 1102 pages | | the FETCH_FAILED line | none; L3 tests with an HTML body on a 503 and on a 200 (devops fix 10) |
| (app) octaveless bottoms | | | **BOTTOM_NO_OCTAVE** (BLOCK, T0+) |
| (app) an earlier list disagrees | | | **CONFLICTING_LIST** (BLOCK, T0+) |

The new flags join `FLAG_ORDER` in `src/engine/importer.js:25-31` as BLOCKs. Status still follows the worst level (`src/engine/importer.js:229`). `{parens: "bottom"}` and `{ding: i}` combine.

### 4.4 Fetch guards (O1) and abuse control (O11)

- **URL.**
  - `http:` or `https:` only, ports 80 and 443 only. The worker checks the port itself, because `allow_custom_ports` is on.
  - Reject IP-literal hosts (v4, v6, decimal and hex forms), `localhost`, `*.local`, `*.internal` and single-label hosts.
  - These guards and the redirect rule below are the SSRF control (devops fix 12). `global_fetch_strictly_public` is also set, but it only routes fetches to the account's own zones over the public internet (3.1).
- **Redirects:** `redirect: 'manual'`, at most 3 hops, with every hop re-checked against the URL rules.
- **Size and time.**
  - A 3 MB byte cap on the streamed body, an 8 s total time cap, and `text/html`, `application/json` or `text/plain` only.
  - The handler takes its clock and its timer as arguments, `createHandler({fetch, now, sleep})`. The L2 test of a 9 s stall advances a fake clock and never waits 9 s (eng P3).
- **Charset (eng fix 8).**
  - Decode the body with the charset from `Content-Type`. Failing that, use a `<meta charset>` or `<meta http-equiv="Content-Type">` in the first 1,024 bytes. Failing both, use UTF-8. Decoding goes through `TextDecoder`.
  - L2 fixture tests:
    - a Shift_JIS page whose note names decode correctly;
    - a Latin-1 page whose `Ré3` and `Sib3` decode correctly.
  - Whether the Workers runtime's `TextDecoder` accepts `shift_jis` is UNVERIFIED. If it does not, such a page answers FETCH_FAILED and the app falls back to paste; the worker never guesses UTF-8 for it.
- **The extraction seam (eng fix 5).** HTMLRewriter does not exist in node.
  - Window extraction is a pure function over the decoded page text: `extractWindow(text) -> {text, pitchTokens}`, in `worker/src/extract.mjs`. `node --test` tests it directly.
  - In the Worker, HTMLRewriter is only a thin streaming wrapper. It collects text nodes, skipping `script`, `style`, `nav` and `footer`, into a string that it hands to `extractWindow`. The wrapper holds no other decision.
- **Shortcuts.** Each one is subject to the NO_TEXT rule of 4.2.
  - A Shopify host uses `<url>.json`, so only the body text is kept. It is detected from the `x-shopify-stage` / `powered-by` headers, or from `/products/` plus a `.json` that returns `product.body_html`.
  - Otherwise, a JSON-LD `Product.description`.
  - Otherwise, the HTMLRewriter text window.
- **Request headers:** no cookies and no `Referer`. A fixed UA names the app and links the About section.
- **Abuse (O11), no Turnstile.**
  - **Origin allow-list:** `https://handpan.raywu.org` and `https://handpan-cards-dev.pages.dev`, enforced through CORS (4.2).
  - **Rate limit.**
    - The Rate Limiting binding allows 10 requests per 60 s per key `Origin + client key`.
    - The client key is `cf-connecting-ip` cut to its /24 for IPv4 and its /48 for IPv6 (eng P3).
    - The binding's docs advise against IP keys (3.1), because many users can share one address, and a coarse prefix makes that worse behind an office or carrier NAT. It is accepted because there is no account to key on.
    - The binding's counters are per location, and its pricing is UNVERIFIED.
  - **Daily budget (D-C).**
    - Each environment has one SQLite-backed Durable Object that counts `/v1/read` calls per UTC day.
    - Production refuses past **3,000** a day and dev past **300**, with 503 BUDGET_SPENT.
    - The two counters are separate objects in separate Workers, so a dev flood stops at 300 and cannot spend production's budget.
    - 3,000 is about 9 times the high volume estimate (3.4: 10,000 a month, about 330 a day) and 3% of Free's 100,000.
  - **The account-wide Free limit (D-C).**
    - Free's 100,000 requests a day is shared by every Worker on the account, and a request the Worker refuses still counts. Past the limit, the answer is Error 1027.
    - So the budget counter bounds upstream fetches, not the account limit. The hard stop in 4.6 bounds that.
  - **Burst:** Free also limits a Worker to 1,000 requests a minute (3.1). The rate limit sits far below it.
  - **CPU:** `[limits] cpu_ms = 50` in `wrangler.toml` (D-C). On Free the platform's 10 ms applies anyway, and whether Free accepts the key is UNVERIFIED (3.1).
  - A non-browser client can forge the `Origin` header, so the counters, the budget and the hard stop are the real bound. The allow-list only stops casual embedding.

### 4.6 Kill switch, hard stop and spend

- **`IMPORT_PAUSED` is a `[vars]` entry**, set per environment in `worker/wrangler.toml` (devops fix 13). It is not a secret: it is not sensitive, and it belongs in the file that deploys it. Set to `"1"`, it makes `/v1/read` answer 503 PAUSED.
  - A dashboard edit of the var takes effect at once, but the next `wrangler deploy` overwrites it with the file's value (3.1).
  - So pausing has two parts: edit the dashboard for an immediate stop, then commit `IMPORT_PAUSED = "1"` so that a later deploy cannot silently un-pause.
- **PAUSED is not a hard stop.** A paused Worker still runs and still counts toward Free's 100,000 a day. On Paid, every request still bills.
- **The hard stop (devops fix 9).**
  - Disable the Worker's `workers.dev` route, in the dashboard (the Worker's Settings, Domains & Routes; label UNVERIFIED) or with `workers_dev = false` and a deploy. Requests then never reach the Worker, so they neither bill nor count against the Worker's limits.
  - If `raywu.org` is a Cloudflare zone (UNVERIFIED), the stronger alternative for production is a custom domain with a zone WAF rate-limit rule in front of the Worker (3.1). The dev Worker stays on `workers.dev`.
- **Usage notification (devops fix 9).**
  - The owner sets a Cloudflare notification that emails at 50% of Free's daily requests (dash, Notifications). Whether Free offers a Workers usage alert, and at which thresholds, is UNVERIFIED.
  - If none is offered, a daily look at the dashboard during 2c is the substitute. 2d does not go live without one of the two.
- **Spend.** No paid API is called.
  - On Free, the launch plan (D-C), the cost is $0. Past 100,000 requests a day, every Worker on the account answers Error 1027 until the reset, and the app maps that page to FETCH_FAILED (4.2).
  - On Paid: $5.00 a month plus $0.30 per million requests past 10M, with **no hard spend cap**. Every request that reaches the Worker bills, 503 PAUSED included. That is why Paid is taken only if CPU forces it, and why the hard stop is the route, not the var.
- **Telemetry for 2c (devops fix 11).**
  - Per request, the Worker writes one Workers Analytics Engine data point: `blobs: [statusCode, source]`, `doubles: [bytesBucket]`. It carries no URL, host, path, IP or Origin.
  - A Worker cannot read its own CPU time, because its clock advances only on I/O (UNVERIFIED; developers.cloudflare.com/workers/reference/security-model/, not re-read). So the 2c CPU figure comes from the dashboard's per-Worker CPU-time percentiles, and the bytes bucket stands in for it per request.
  - If Analytics Engine is not on Free (UNVERIFIED), the dashboard's request, error and CPU metrics are the only 2c source, and the per-source split is not measured.
- **Deploy hygiene (devops fix 13).**
  - Every owner command runs one pinned wrangler, `npx wrangler@<version>`. The exact version is named in the header comment of `worker/wrangler.toml`. L2 picks a release at least two weeks old, and an L2 test checks that the comment names an exact version, with no `^`, `~` or `latest`.
  - Each deploy records its commit: `npx wrangler@<version> deploy --env <env> --message "$(git rev-parse HEAD)"`. The `--message` flag is UNVERIFIED. If it is absent, the owner tags the commit `worker-<env>-<date>` before deploying.

### 10.3 The extract endpoint and the span check

Flow: when READ LINK or IMPORT ends INSUFFICIENT or in a parens BLOCK, an explicit ASK THE MODEL tap (O4) sends the text to `POST /v1/extract`, behind the budget and kill switch. The app runs the span check on the returned roles. A failure is a BLOCK, SPAN_MISS or MODEL_DROPPED_NOTE, and writes nothing. A pass rebuilds labelled text, runs `interpret`, and shows the preview with a MODEL_ROLES CONFIRM.

`POST /v1/extract`. Body `{"text": "<= 8000 chars"}`. Response 200:

```
{"roles": {"ding": {"note": "D3", "at": 41}, "top": [{"note": "A3", "at": 45}, ...], "bottom": [...]}, "model": "claude-haiku-5-5", "costMicros": 500}
```

`at` is a character offset into the same `text`. The model returns roles and offsets only. It never returns an engine scale string, so it cannot write syntax that is not in the source. Its JSON schema caps `top` at 30 and `bottom` at 12.

| Code | HTTP | App behaviour | Import flag |
|---|---|---|---|
| NO_LIST (extract) | 422 | the existing INSUFFICIENT line | NO_NOTE_LIST (BLOCK) |
| BUDGET | 503 | "Import from links is paused. Paste the notes instead." | none |
| (app) span check fails | | preview shown, USE disabled | **SPAN_MISS** (BLOCK) |
| (app) a pitch token in the text is in no role | | preview shown, USE disabled | **MODEL_DROPPED_NOTE** (BLOCK; the after-list principle, A1n `docs/plans/2026-10-16-scale-import.md:785`) |
| (app) roles accepted | | a tick needed before USE | **MODEL_ROLES** (CONFIRM) |

The check runs twice: in the worker before it answers, and in the app. Only the app's run is authoritative.

1. For every role entry, `text.slice(at, at + len)` must fold (en dash, Unicode accidentals, solfège, prefix flats; the same fold as `check-gold.cjs:12-13`) to the entry's note name. The octave digit is optional only where the source has none, and then NO_OCTAVE applies as today.
2. Each offset is used once, and the count of each note name in the roles must not exceed its count in the text window.
3. At least 5 distinct spanned pitches, otherwise NO_NOTE_LIST. A bare name such as "D Kurd 10" has no pitch tokens, so it fails (O10).
4. Every pitch token in the window that is in no role gives MODEL_DROPPED_NOTE, the after-list scan applied to the model tier. A reference pitch (`A4 = 440 Hz`) is exempt by the same REFERENCE rule as A1n.
5. The app then **rebuilds labelled text** (`Ding: D3\nTop: A3 Bb3 ...\nBottom: F3 G3`) from the spans and passes it to `interpret`. Every existing flag and the preview apply unchanged, and `serialise` writes the syntax. The model's output never reaches `#scale-box` except through `interpret` and USE.

### 10.4 Provider caps

Four layers, any one of which stops spend:

1. **Env `IMPORT_PAUSED=1`** makes both endpoints answer 503 PAUSED. Toggling it is an owner action in the dashboard or `wrangler secret put`.
2. **Durable Object daily counter.** `/v1/extract` refuses with 503 BUDGET after N calls a UTC day. N defaults to 1,000, which is $0.50 a day at Haiku prices, ESTIMATE.
3. **The provider's own cap**, which the owner sets in 10.5:
   - Anthropic workspace spend limit: a hard stop (support.claude.com/en/articles/9796807).
   - OpenAI project hard budget: returns 429 (developers.openai.com/api/docs/guides/spend-limits).
   - Workers AI free neurons.
   The worker maps 402, 429 and the Anthropic billing refusal to 503 BUDGET.
4. **Prepaid credit with auto-reload off.** Even a lagging cap cannot exceed the balance.

AI Gateway spend limits are an open beta and soft (blog.cloudflare.com/ai-gateway-spend-limits/), so they are not relied on.

### 10.6 The gate

**Gate (Phase 1's 2b, unchanged):** Tier 2 eval, offline. A script under `docs/plans/import-v2-eval/` calls Haiku 5.5 and gpt-6-luna with the owner's keys on the 40 gold texts, 3 runs each, applies `fromRoles`, and reports exact, wrong-but-valid and cost per import. **Gate:** 0 wrong-but-valid and a lift of 3 or more of the 4 prose cases. Otherwise cut `/v1/extract`.

If the gate passes, the lanes gain: in L1, `fromRoles(text, roles)` passing span-check rules 1–5 of 10.3, with a test where the roles omit a pitch (MODEL_DROPPED_NOTE) and one where an offset points at a different note (SPAN_MISS); in L2, `/v1/extract`, the span check before it answers, BUDGET on 503 and a provider 402 or 429 mapped to BUDGET; in L3, ASK THE MODEL, a MODEL_ROLES tick, the GA `source` value `model`, and an About sentence naming the AI provider. Q1 (Haiku 5.5 first, then gpt-6-luna on 503/429) and Q7 (a daily extract cap of 1,000) take their Phase 1 defaults.
