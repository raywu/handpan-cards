## 1. Goal, non-goals, standing owner gates

**Goal (one testable sentence).** A user can paste a product URL or text into the Add sheet and get a REVIEW preview whose every pitch is a span in the source text. Run against the 28 REVIEW gold cases, that holds on at least 24, with 0 wrong-but-valid. With the worker down, paste import behaves exactly as it does on `087a4a8`.

The command that checks it is the gold replay in lane L1/L3 (section 7): `node --test tests/import_gold.test.js`. It replays the committed fixture `tests/fixtures/import_gold_v1.json`, which is derived from the gold file.

**Non-goals.**

- No frontier model, at any tier (O3). Their prices are listed in 3.4 for comparison only.
- No notes from a name. A bare scale or model name stays INSUFFICIENT (O10): "D Kurd 10" never produces pitches, at any tier.
- No unreviewed write to `#scale-box`. Every tier ends in the existing preview and its CONFIRM ticks; USE stays the only writer (O9).
- No change to the GitHub Pages deploy of `index.html`.
- No build step in `index.html`. The worker is a separate artifact under `worker/`.
- No content logging and no training use (O4).
- No vision in Phase 2. It is its own later phase (section 8, O5).
- No preset picker (section 3.5).

**Standing owner gates.**

- Every key, account, billing setting and deploy is OWNER-ONLY (section 6).
- Production goes live only when the owner unhides the import row on main and sets `IMPORT_ENDPOINT`. Both are one-line changes, and each is its own PR.
- The gold spot-check (O6) gates the Phase 2 numbers.
- Lane merges follow the AFK and main gates unchanged.

### 2.2 Wrong-but-valid (reported separately, as O6 requires)

Both are NEEDS_INPUT cases that tier 0 returns as REVIEW. The only guard is the NO_OCTAVE CONFIRM tick, which is far too weak for a wrong pan.

1. **yatao-c-ashakiran-15.** Span: `Top Notes: C - F, G, A, B, C, D, E, G` / `Bottom Notes: D, E, F, A, B, C`.
   - Tier 0 gives `(C3) F3 G3 A3 B3 C4 D4 E4 G4 [D5] [E5] [F5] [A5] [B5] [C6]`. It chains the octaveless bottoms upward after the top, so they come out an octave or more too high.
   - The truth is not recoverable from the text.
   - **Fix (T0+, required before any tier ships):** an octaveless bottom list gets a BLOCK, `BOTTOM_NO_OCTAVE`. Bottom notes are never chained from the top.
2. **boullard-battiloro-celtic-contradictory.** Span: `D A C D E F G A C` then `Notes : D A C D E F G A C D`. That is 9 against 10 notes.
   - Tier 0 takes the labelled 10-note line and ignores the unlabelled 9-note line above it.
   - **Fix (T0+):** the after-list scan already blocks a later note run. Extend it to an earlier run of five or more note tokens that disagrees with the chosen list (BLOCK `CONFLICTING_LIST`).

One more case is a source error, not an importer error. thomann-startone-d-kurd-octaveless is `D / A, B, C, …`: the shop prints B where the Kurd has Bb. Tier 0 reproduces the text exactly, which is correct behaviour, but the user gets a wrong pan.

No tier can catch this without inventing a note, and inventing notes is forbidden. The plan's answer is the scale-name cross-check in Open Question Q4: an INFO line when the name says Kurd and the set disagrees. It writes nothing.

**Pick: Cloudflare Workers**, on Free first. Whether 10 ms of CPU is enough to parse a 2.4 MB page is UNVERIFIED; time spent waiting on a fetch is not CPU. Phase 2 measures it. Go to Paid ($5) if the CPU limit is hit.

SSRF facts:

- `global_fetch_strictly_public` exists (developers.cloudflare.com/workers/configuration/compatibility-flags/).
- `allow_custom_ports` is on by default there, so the worker must check the port itself.
- Whether Workers refuse private-IP targets or resist DNS rebinding is **UNVERIFIED**. One community report of an exception on an IP-literal hostname exists (community.cloudflare.com/t/exception-when-fetching-url-with-ip-hostname-in-workers/595868). The worker therefore refuses IP literals itself, whatever the platform does.

Abuse control (O11):

- The Rate Limiting binding allows only 10 s or 60 s periods, and its counters are per location. The docs advise against keying on IP (developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/). Its pricing is UNVERIFIED.
- KV is eventually consistent (developers.cloudflare.com/kv/concepts/how-kv-works/), so it cannot hold a budget counter.
- Durable Objects need Paid: 1M requests included, then $0.15/M (developers.cloudflare.com/workers/platform/pricing/).
- Turnstile needs `api.js` from challenges.cloudflare.com (developers.cloudflare.com/turnstile/get-started/client-side-rendering/). That would be a second external script and break the single-external-script rule in `CLAUDE.md` "Hard constraints". **Rejected.**
- A WAF rate-limit rule and a custom domain both need a zone (developers.cloudflare.com/waf/rate-limiting-rules/ , /workers/configuration/routing/custom-domains/). Both are optional.

Operations:

- Workers Logs are on by default, keep 3 or 7 days, and are turned off with `observability.logs.invocation_logs = false` (developers.cloudflare.com/workers/observability/logs/workers-logs/). Whether `console.log`-free code still records request URLs in the invocation log is **UNVERIFIED**, so turn the logs off.
- Secrets are set per environment (developers.cloudflare.com/workers/configuration/secrets/ , /workers/wrangler/environments/).
- Rollback covers the last 100 versions (developers.cloudflare.com/workers/configuration/versions-and-deployments/rollbacks/).
- CI deploy would use wrangler-action@v4 with an "Edit Cloudflare Workers" token (developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/). It is not recommended for Phase 2 (section 6).
- `@cloudflare/vitest-plugin` exists (developers.cloudflare.com/changelog/post/2026-08-19-vitest-plugin/), but it adds npm. The plan tests the worker as a plain module under `node --test` instead (lane L2).
- Rendering fallbacks, not needed on this set (3.3):
  - Browser Rendering: Free 10 min/day; Paid includes 10 h, then $0.09/h (developers.cloudflare.com/browser-rendering/pricing/).
  - Jina Reader: 20 RPM (jina.ai/reader/). It is a third party that would see the URL.

### 3.5 Option P: the preset picker

P lets the user pick a ding and a catalog entry. The only permissive catalog found is handpaner.com's: 77 entries and 64 names, extracted from https://handpaner.com/nuxt/bd049b5.js (build 2025-04-19).

- Its source repo, Robhub/handpaner, is MIT, "Copyright (c) 2020 Robin".
- The site's own terms are **UNVERIFIED**; its privacy page says "Commercial".
- Kirstein, MAG, Schlagwerk, IDM and Sound Sculpture all publish scale lists under ordinary copyright.
- The catalog is **not committed**. `pcoverage.cjs` records its sha256 and the results keep entry names only.

|---|---|---|

| pc-only | 15 | Only the pitch-class set matches: **a different pan**. Picking it is a silent wrong pan. |
| none | 1 | yatao-d-aegean-18 |

Findings:

- **P beside tier 0:** T0 exact 12/32, P exact 9/32, union 18/32.
- **P cannot represent most modern listings.** 12–19-note pans with bottom notes are 15 of the 32. Wherever both could answer, P overlaps with T0+.
- P re-opens a decision the owner already made. Presets were removed on 2026-09-10 in commit 30c329e ("drop the presets"), with the owner quote "I don't know if we need the preset options" (`docs/SCALE_ENGINE_PLAN.md:589-594`). v1 gate G4 is "no preset offer" (`docs/plans/2026-10-16-scale-import.md:739-751`).

**Option P is evaluated three ways and rejected in all three:**

- **As a competitor:** 28% exact, against T0+'s 22–24 of 28 REVIEW cases.
- **As a complement:** over tier 0 it adds 6 exact cases. T0+ fixes 3 of them deterministically (yatao-a2, gladfresit, mag-blog). Engadine and kalopho are prose cases tier 2 targets, and idm-celtic is image-only, where a picker guesses from the name alone, which O10 forbids for every tier.
- **As P + cascade:** the most complex option, and it keeps P's silent-wrong-pan risk.

## 4. Architecture

### 4.1 Request flow

```
  Add sheet (index.html, app block)                 worker/ (Cloudflare Worker)
  ---------------------------------                 ---------------------------
  [paste box] --IMPORT--> interpret(text)  (local, no network, as today)
                               |
                               v
                         preview + flags --USE (O9)--> #scale-box
                               ^
  [URL field] --READ LINK--> POST /v1/read {url} ----> guards (4.4) -> fetch
     (explicit tap, O4)        |                       shopify .json | JSON-LD | text window
                               | <---- {text, source, finalUrl, truncated}
                               v
                     interpret(text)  (local, tier 0 / T0+)
                               |
              REVIEW? -- yes --> preview (as above)
                 | no (NO_NOTE_LIST or a parens BLOCK only)
                 v
     [ASK THE MODEL] (explicit tap, O4) --> POST /v1/extract {text} --> budget + kill switch
                               | <---- {roles:{ding,top,bottom} each with {note, at}}
                               v
               spanCheck(text, roles)  (local; the worker runs the same check first)
                               |
              fail --> BLOCK SPAN_MISS / MODEL_DROPPED_NOTE (nothing written)
              pass --> labelled text --> interpret() --> preview + CONFIRM MODEL_ROLES
```

The worker is never in the path of a paste. If either worker call fails, the app keeps the text it has, shows the error line, and paste import still works.

### 4.2 API contract

`POST /v1/read`. Body `{"url": "<http(s) URL>"}`. Response 200:

```
{"text": "...", "source": "shopify-json" | "json-ld" | "html", "finalUrl": "...", "bytes": 123, "truncated": false}
```

`text` is at most 60,000 characters. For `html` it is the window around the densest pitch run, at most 8,000 characters.

`POST /v1/extract`. Body `{"text": "<= 8000 chars"}`. Response 200:

```
{"roles": {"ding": {"note": "D3", "at": 41}, "top": [{"note": "A3", "at": 45}, ...], "bottom": [...]}, "model": "claude-haiku-5-5", "costMicros": 500}
```

`at` is a character offset into the same `text`. The model returns roles and offsets only. It never returns an engine scale string, so it cannot write syntax that is not in the source. Its JSON schema caps `top` at 30 and `bottom` at 12.

| Code | HTTP | App behaviour | Import flag |
|---|---|---|---|
| BAD_URL | 400 | "That is not a web link." Paste stays usable | none (no result) |
| BLOCKED_HOST | 403 | "That address cannot be read." | none |
| TOO_LARGE | 413 | "That page is too large. Paste the notes instead." | none |
| NOT_HTML | 415 | same wording, "not a web page" | none |
| NO_TEXT | 422 | "No text found on that page." | none |
| NO_LIST (extract) | 422 | the existing INSUFFICIENT line | NO_NOTE_LIST (BLOCK) |
| RATE_LIMITED | 429 | "Too many imports. Try again in a minute." | none |
| FETCH_FAILED, UPSTREAM_BLOCKED | 502 | "That site did not answer. Paste the notes instead." | none |
| PAUSED, BUDGET | 503 | "Import from links is paused. Paste the notes instead." | none |
| TIMEOUT | 504 | same as 502 | none |
| (app) span check fails | | preview shown, USE disabled | **SPAN_MISS** (BLOCK) |
| (app) a pitch token in the text is in no role | | preview shown, USE disabled | **MODEL_DROPPED_NOTE** (BLOCK; the after-list principle, A1n `docs/plans/2026-10-16-scale-import.md:785`) |
| (app) roles accepted | | a tick needed before USE | **MODEL_ROLES** (CONFIRM) |
| (app) octaveless bottoms | | | **BOTTOM_NO_OCTAVE** (BLOCK, T0+) |
| (app) an earlier list disagrees | | | **CONFLICTING_LIST** (BLOCK, T0+) |

The new flags join `FLAGS` in `src/engine/importer.js:20-30`. Status still follows the worst level (`src/engine/importer.js:229`).

### 4.3 Span check (the O2 safeguard)

The check runs twice: in the worker before it answers, and in the app. Only the app's run is authoritative.

1. For every role entry, `text.slice(at, at + len)` must fold (en dash, Unicode accidentals, solfège, prefix flats; the same fold as `check-gold.cjs:12-13`) to the entry's note name. The octave digit is optional only where the source has none, and then NO_OCTAVE applies as today.
2. Each offset is used once, and the count of each note name in the roles must not exceed its count in the text window.
3. At least 5 distinct spanned pitches, otherwise NO_NOTE_LIST. A bare name such as "D Kurd 10" has no pitch tokens, so it fails (O10).
4. Every pitch token in the window that is in no role gives MODEL_DROPPED_NOTE, the after-list scan applied to the model tier. A reference pitch (`A4 = 440 Hz`) is exempt by the same REFERENCE rule as A1n.
5. The app then **rebuilds labelled text** (`Ding: D3\nTop: A3 Bb3 ...\nBottom: F3 G3`) from the spans and passes it to `interpret`. Every existing flag and the preview apply unchanged, and `serialise` writes the syntax. The model's output never reaches `#scale-box` except through `interpret` and USE.

### 4.4 Fetch guards (O1)

- **URL:** `http:` or `https:` only, ports 80 and 443 only (the worker checks this, because `allow_custom_ports` is on). Reject IP-literal hosts (v4, v6, decimal and hex forms), `localhost`, `*.local`, `*.internal` and single-label hosts. Set `global_fetch_strictly_public`.
- **Redirects:** `redirect: 'manual'`, at most 3 hops, with every hop re-checked against the URL rules.
- **Size and time:** a 3 MB byte cap on the streamed body, an 8 s total time cap, and `text/html`, `application/json` or `text/plain` only.
- **Shortcuts:** a Shopify host (detected from the `x-shopify-stage` / `powered-by` headers or `/products/` plus `.json` returning `product.body_html`) uses `<url>.json`, so the body text is all that is kept. Otherwise a JSON-LD `Product.description` with five or more pitch tokens. Otherwise the HTMLRewriter text window.
- **Request headers:** no cookies and no `Referer`. A fixed UA names the app and links the About section.
- **Abuse (O11), no Turnstile:**
  - An `Origin` allow-list: `https://handpan.raywu.org`, `https://handpan-cards-dev.pages.dev`.
  - The Rate Limiting binding at 10 requests per 60 s per (Origin, coarse client key).
  - A Durable Object daily counter.
  - The provider's hard cap (4.6).
  - An `Origin` header can be forged by a non-browser client, so the counters and caps are the real bound. The allow-list only stops casual embedding.

### 4.5 What stays local, and the worker-down proof

Local and unchanged:

- Paste import.
- `interpret`, `serialise` and every flag.
- The preview, ticks and USE.
- The share link.
- All storage.
- GA, which still records `{status}` only (`index.html:10832`).

The worker sees:

- the URL, on READ LINK;
- the text window, on ASK THE MODEL.

It sees nothing else: no deck, no storage, no GA id.

**Worker down, or `IMPORT_ENDPOINT` empty:**

- READ LINK shows the 502/503 line, or is not rendered at all when the endpoint is empty.
- IMPORT on pasted text runs exactly the `087a4a8` code path plus the T0+ notation rules.
- New test (L3): "IV2: with the endpoint unreachable, a paste import makes no fetch, and every IM test still passes".

### 4.6 Kill switch and hard cap

Four layers, any one of which stops spend:

1. **Env `IMPORT_PAUSED=1`** makes both endpoints answer 503 PAUSED. Toggling it is an owner action in the dashboard or `wrangler secret put`.
2. **Durable Object daily counter.** `/v1/extract` refuses with 503 BUDGET after N calls a UTC day. N defaults to 1,000, which is $0.50 a day at Haiku prices, ESTIMATE.
3. **The provider's own cap**, which the owner sets in section 6:
   - Anthropic workspace spend limit: a hard stop (support.claude.com/en/articles/9796807).
   - OpenAI project hard budget: returns 429 (developers.openai.com/api/docs/guides/spend-limits).
   - Workers AI free neurons.
   The worker maps 402, 429 and the Anthropic billing refusal to 503 BUDGET.
4. **Prepaid credit with auto-reload off.** Even a lagging cap cannot exceed the balance.

AI Gateway spend limits are an open beta and soft (blog.cloudflare.com/ai-gateway-spend-limits/), so they are not relied on.
