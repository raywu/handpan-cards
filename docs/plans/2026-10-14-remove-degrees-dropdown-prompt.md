# Plan-drafting prompt: remove the DEGREES dropdown, infer the parent always

Owner request, 2026-10-13, verbatim:

> "Why can we not infer the mode from every scale? I don't think the user will want to override the mode for different labels. Let's remove degrees dropdown unless there's a strong use case someone would want different modes for labels."

Then "Afk". The coordinator searched for a strong use case and found none (AFK auto-pick D1, recorded in memory `queued-remove-degrees-dropdown`): the only case where the override changes a label is a tie between two parents on a pan missing the separating step (a D minor hexatonic without a 6th reads Aeolian by list order; Dorian would relabel G from `iv` to `IV`). The owner confirmed on 2026-10-14 ("Start it") that this runs after the sheet-guidance workstream, which merged as main `b6d8bee`. The prompt below is what the planning agent receives, unchanged. Everything after "## Quality rubric" is the coordinator's record and is not part of it.

### The request

The Edit page of the scale sheet (`#scale-sheet`, the owner's "drawer") carries a native `<select>` labelled DEGREES (`#scale-degrees` in `#scale-degrees-row`, filled by `buildDegrees()` from `HPE.naming.PARENTS`). It lets the player override the parent scale the engine infers for degree labels (SCALE_ENGINE_PLAN decision D10, "the parent-scale override lives in the Edit sheet, never on the create path"). The owner wants it gone: the engine already infers a parent for every scale (`HPE.naming.inferParent`, ENGINE-SPEC section 10: "A parent is always inferred - every candidate has a finite distance"), and nobody will want a different mode just to change labels. Four requirements are binding:

1. **The dropdown and its row leave the Edit page.** `#scale-degrees-row`, `#scale-degrees`, `buildDegrees()`, the `degSel` change listener (`resyncSheet(true)`), the `degSel` tab stop in the sheet's Tab trap, and the `degSel.value` member of `sheetKey()` are removed, together with every CSS rule that names `#scale-degrees` (the 16px iOS rule, the 44px/48px min-height rules, the `font` rule, and the plate-band `:focus-within` rule that goes static for the name and the degrees, if one exists at your SHA: find them all). The Edit page's remaining rows (name, delete) keep their order and behaviour.
2. **SAVE writes no parent.** `sheetOptions()` stops setting `o.parent`; the engine infers it (`select.build` resolves a null or absent `seedOptions.parent` through `inferParent`, asserted by `tests/select.test.js` "options report palette, mirror and the RESOLVED parent index"). `options.parent` therefore reads as the INFERRED index on every deck the app saves from now on, exactly as it does on the create path today.
3. **Nothing stored or shared breaks.** The engine, `core.parseSeed`'s validation of `options.parent` (0-10, integer, else `BAD_NOTE`), the share format (`src/engine/share.js` v3 options line `palette \t parent \t mirror \t anchor \t name`, decoded to `parent: null` when empty) and every fixture digest (`engine_corpus_v1`, `app_surface_v1`, `pan_render_v1`, `card_face_v1`, `deck_ids_v1`) are untouched. A stored custom record or a share link that carries an explicit parent index keeps the labels it was saved with when it is DISPLAYED (decision R-1 below says what happens when it is next SAVED). The deck id never depends on options (D14), so no id moves.
4. **Every test and mutant that the removal defeats is re-pointed or replaced, never deleted without a replacement, and the mutant count never drops.** Inventory at your SHA (verify each; cite titles, ids and functions, never line numbers): `tests/app.test.js` "the Degrees select lists the parent candidates with the inferred one preselected" (killed by mutant `d_degrees_ignored`), "LF F-5: changing the degree select re-parses the seed with the new parent" (mutant `r4f_degsel_change_unwired`), "changing only an option keeps the deck id and moves the share URL" (sets `#scale-degrees` as one of its option changes), the `editRowsShown` helper and every test that lists `scale-degrees-row` among the Edit rows ("tapping the already-selected custom chip opens the sheet in Edit state, prefilled", "editable defaults: saving each seeded deck with a palette change mints the fixture id as its replacement in the seeded slot", and any other), "the sheet's text inputs stay at 16px in every rule that sets their size, media blocks included" (iterates `#scale-degrees`), the two tests that read `options.parent` only to call `HPE.select.autoName` (unaffected: say so). `tests/e2e.test.js` "DR1 line 86: on Edit the band goes static for the name and the degrees, and not for a drawer control", "the selected custom chip reopens the sheet in Edit state, prefilled, at 380px" (reads `scale-degrees-row` and the option count), "Tab is trapped inside the Edit sheet and reaches every Edit control" (expects `scale-degrees` among the stops). `tools/sandbox.js` `ELEMENT_IDS` lists `scale-degrees-row` and `scale-degrees`: removing an id from the markup removes it from `ELEMENT_IDS` in the same change (the sandbox stubs only ids that exist; `tests/app.test.js` "SG: N-A3 no served id is removed and the wrapper is markup-only" is the model for the assertion that an id list and the markup agree, read it before deciding how to assert the removal). Mutant `b_degree_missing` is a DATA mutant on `data/decks.json` and is not involved; say so. `r4e_naming_degrees_parent_unnamed` is an engine mutant and is not involved; say so.

### Facts already established (verify each against the SHA you read)

- **The engine needs no change.** `select.build` already infers when `seedOptions.parent` is null or undefined and still honours an explicit index; `core.parseSeed` already validates one; `share.js` already encodes an empty parent as `""` and decodes it as `null`. A plan that touches `src/engine/` to achieve the owner's request has misread it. The engine corpus fixture is regenerated only on a deliberate engine output change, and there is none.
- **Create path.** `sheetOptions()` sets `o.parent` only when `editingId` is truthy, so the create path infers today and is unchanged.
- **`sheetKey()`** is the tuple a seeded sheet is compared against to tell an unchanged SAVE (`scaleBox.value, nameBox.value, palette, mirror, bottomMirror(), anchor, degSel.value, seatsKey(layoutSeats)`). Dropping `degSel.value` cannot turn a changed sheet into an unchanged one, because nothing else on the sheet can set the parent; say which test pins the unchanged-SAVE path (the seeded SAVE / DELETE suite, "SD:" prefix) and that it stays green.
- **The auto name.** `select.autoName(fields, parentIndex)` names a deck after its inferred or overridden parent. With the override gone, a custom deck's auto name is the inferred parent's; a record saved under an override keeps its stored `name` (names are stored, never recomputed, by the seeded SAVE / DELETE and editable-defaults work: cite the test).
- **Focus and the keyboard.** `#scale-degrees` is in the sheet's Tab-trap list and was one of the two controls for which the plate band goes static (DR1 line 86). Removing a 48px row from `.sheetbody` SHORTENS the Edit page's scroll; no pinned row changes, so the footer and the keyboard budget measured for the sheet-guidance plan are unchanged. Say so in the risk register rather than measuring again.
- **The oracle.** The full e2e suite starves the local browser; CI at the head SHA is the evidence; single e2e tests run locally with `--test-name-pattern`.
- **Not involved.** `#settings-panel` and `panel-fit`; `data/decks.json`; `const DECKS`; print (`tools/`); `docs/ENGINE-SPEC.md`'s engine rules (the spec's statement that the override travels in the seed options stays TRUE; only the sentence that the Edit sheet exposes it needs a mark).

### What the plan must settle

**A. R-1, the override on re-save.** A custom record saved before this change with an explicit non-inferred parent is opened in Edit and saved again. Options: (a) SAVE always re-infers (the owner's words, "infer parent always"; the stored override is dropped silently at the next save, and the labels may change on that save), (b) SAVE preserves the stored index unless the fields changed (no label ever changes without a field edit, at the cost of a hidden option the UI can no longer see or clear). Recommend (a) and say why in one sentence; (b) is the conservative branch and must be described well enough that the owner can pick it. Whichever wins, a DISPLAYED record or share link with an explicit index keeps its labels (requirement 3). State the test that proves the recommended behaviour (a record with `options.parent` set to a non-inferred index, opened and saved: `options.parent` after equals the inferred index and the degrees are relabelled) and its mutant.

**B. R-2, `seedParent()`.** It exists only to preselect the dropdown for a seeded deck. Recommend removal with the dropdown unless another caller exists at your SHA.

**C. R-3, the share-link decode path.** A link carrying an explicit parent index decodes and displays with that index today. Keep it (recommended: the format and the engine are untouched; the only producer of a non-null index is gone, so the field decays naturally) and name the test that already asserts the decode (search `tests/app.test.js` and `tests/share.test.js` for `parent`).
