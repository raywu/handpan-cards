## 1. Goal and non-goals

**Goal:** after the app lane merges, selecting any deck in the production app leaves a URL in the address bar that reloads, bookmarks and copies to that same deck (`#s=<code>` for a custom deck, `#deck=<slug>` for a seeded one), and one visible panel control copies that URL and announces "LINK COPIED"; the checks are the section 4 tests plus `node tools/probe/panel_fit.js --base origin/main --font fallback` green.

**Non-goals:** no engine change and no edit to `src/engine/share.js` (no new share format version, no `replaces` in the share options, no corpus regen); no deck data or diagram geometry change; no landing pages; no change to W1's listener or route before W1 merges; no new component family, colour or typeface; no hidden gesture (a chip long-press is REJECTED); no `pushState` anywhere in this feature; no audio, stats, SM-2 or PWA.

## 2. Design

**The one rule for the bar (S1, recommended):** the address bar is always a link to what you see. One function decides the text, one function writes it, and every write is `history.replaceState`.

- `shareCode(d)` (eng review R2): the one place the engine is asked for a code, returning `{ ok: true, value: code }` or the engine refusal (the over-cap reason from `HPE.share.encode`, cap `CAPS.payload` 4096 in `src/engine/share.js`). `shareLink(d)` becomes `origin + pathname + SHARE_PREFIX + shareCode(d).value` (same `{ok, value}` shape, SB-4 test unchanged) and `routeFor(d)` becomes `SHARE_PREFIX + shareCode(d).value`; neither re-encodes.
- `routeFor(d)`: for a custom deck (`CUSTOM[d.id]`, which includes an edited seed's replacement record) the `#s=` text when `shareCode` is `ok`, else the empty string with the refusal reason kept for the control. For a seeded deck the inverse of W1's `DECK_SLUGS` gives `DECK_ROUTE + slug` (**W1 adds** both constants).
- `syncRoute()`: returns at once while `sheetOpen` (the bar shows the page route then). Otherwise computes `location.pathname + location.search + routeFor(deck())` and, only if it differs from the bar, calls `history.replaceState(history.state, "", that)`. Then sets the copy control's state: enabled when `routeFor` produced text, disabled with the refusal reason as its `title` otherwise (S5), and on the TRANSITION into the refused state (not on every call) `say(reason, "warn")` once, so touch users, who never see a `title`, hear why (eng review R3). At boot the announcer may already hold a message (edge 7's engine error, or "That deck is gone. Showing <name>."): that message wins, and the over-cap warning is skipped when anything was said at boot (review 1 nit 6; the control is still disabled with its `title`). Idempotent: a second call writes nothing and announces nothing (asserted).

**Write sites** (every one is `syncRoute()`; no other code writes the hash):

| Site | Why |
|---|---|
| the last statement of `selectDeck(id)` | covers chip taps, `openShare`, SAVE (which calls `selectDeck(d.id)` after `closeScaleSheet()` in `runGenerate()`), DELETE of the shown deck (`deleteDeck` calls `selectDeck(fallbackDeck().id)`), RESET SEEDED DECKS, and W1's `hashchange` route (which calls `selectDeck`) |
| the last statement of the go block | boot sets `deckId` directly, not through `selectDeck`; this write replaces a consumed `#s=`, a refused `#s=` (edge 7), and W1's `#deck=` (its own replace-away call is removed, see below) with the canonical route, and gives a hashless boot its route (edge 6) |
| the `popstate` listener, ONLY while `pendingPop` is set | `closeScaleSheet()` runs `history.back()`, which is asynchronous: a `replaceState` issued synchronously after it (the SAVE path: `closeScaleSheet(); ... selectDeck(d.id)`) lands on the entry about to be popped, and the traversal then restores the PRE-SHEET URL. The browser's answering `popstate` is the first moment the restored entry is current, so the listener syncs there (edges 3, 4). `closeScaleSheet()` sets a module flag `pendingPop = true` beside its `history.back()`; the listener's first statement is `if (pendingPop) { pendingPop = false; syncRoute(); return; }`, before the existing `if (!sheetOpen) return;`. The flag is the whole difference between a sheet-close traversal and every other `popstate`: a fragment navigation (an about-section `#deck=` link, Back or Forward between two deck routes) ALSO fires `popstate`, BEFORE `hashchange`, and an unconditional sync there would overwrite the destination hash with the deck still on screen and the guard would then swallow the `hashchange` (outside voice C1, P1, 2026-10-16). Without the flag the listener does nothing to the bar: a stray pop with no page open moves neither deck, focus nor hash (the existing test "a pop with no page open is not an invitation to close something" stays green and gains a `history.calls` length assertion). |

The sheet's own route is untouched: `showSheet` keeps `history.pushState({ scalePage: true }, "", sheetRoute())` on top of the canonical hash, the pop restores the canonical hash (edge 2), and a boot on `#add`/`#edit-` opens nothing, as today; the existing branch's OWN `replaceState` is removed (review 1, option (b)): the branch only drops the page route from its reading, and the final `syncRoute()` writes the deck route, so a page-route boot makes exactly ONE `replaceState` (the page-route removal and the deck route land in the same call) and `tests/app.test.js` "booting on a page route opens nothing and leaves a clean hash" keeps its call list `["replace"]` with the route now `#deck=d-kurd-10`.

**Read sites:** the go block (`openShare` for `#s=`, W1's `routeDeck()` for `#deck=`, both unchanged in what they do) and W1's `hashchange` listener, which this feature changes AFTER W1 merges in two ways: (1) an idempotence guard as its first statement, `if (location.hash === routeFor(deck())) return;`, so the app's own `replaceState` writes (which fire no `hashchange`) and a sheet pop back to the canonical hash (which fires `popstate` first, then `hashchange`, by which time the bar already holds the canonical text) never re-route, never `track("deck_route")` twice and never rebuild the chips; (2) its `#s=` early return becomes `openShare(location.hash.slice(SHARE_PREFIX.length))` (S7). Both read **`location.hash`, never `event.newURL`** (eng review R1): after a SAVE that changed the deck id, the pop restores `#s=<old>`, the `pendingPop` sync replaces it with `#s=<new>`, and the queued `hashchange` may still carry the OLD code in `newURL`; a listener that read `newURL` would re-import the old deck and undo the save. The e2e test for edge 4 asserts no such re-import. Change (2) means an in-page hash change to a share code imports it, which also closes the gap the e2e comment "an in-tab hash paste is a behaviour gap, not a test gap" records. W1's two replace-away calls (the go-block `#deck=` branch and the listener) are deleted: `syncRoute()` at the end of `selectDeck` and of the go block writes the canonical text instead. Section 6 re-verifies every W1 anchor named here.

**The control (S2, recommended placement):** `<button class="mode" type="button" id="share-copy">COPY LINK</button>` beside `+ ADD A SCALE` in the Scales group, the two wrapped in one `.modebar duo` row (`<div class="modebar duo">` around `#deck-add` and `#share-copy`; `#deck-restore` keeps its own line below). `duo`, not bare `.modebar`: `.modebar` is `flex-wrap:wrap`, so two `.mode` buttons would stack at 320px and grow the panel; `.modebar.duo` is `nowrap` with `min-width:0`, narrow padding and `line-height:1.25`, and already carries two labels on one line at every width (the Amy row). Same `.mode` surface, Nunito Sans caps, 44px target, no new family; the row is one control high, so no control below moves and the `panel-fit` oracle's rule 2 (existing controls may not sit lower) and rule 3 (a new control must be on screen) both hold without touching `RES_ALLOWANCE_PX`. `panelStops()` gains `document.getElementById("share-copy")` and `document.getElementById("share-url")` right after `document.getElementById("deck-add")`; `isStop` already drops the button while disabled and the input while hidden. Both ids join `ELEMENT_IDS` in `tools/sandbox.js` (the stub's `getElementById` throws for an unregistered id) and the stub element gains a no-op `select()` (outside voice C2). Click handler `copyLink()`: reads `location.href` (never a fresh encode; the bar is the truth), tries `navigator.clipboard.writeText(href)`, on rejection or absence tries `navigator.share({ url: href })`, and failing both reveals a readonly `<input id="share-url" readonly>` under the row holding the href, selected (`select()`), hidden again on the next panel close. The announcer says which: `say("LINK COPIED", "ok")`, `say("LINK SHARED", "ok")`, `say("SELECT THE LINK AND COPY IT", "warn")`. A `navigator.share` rejection named `AbortError` is the user closing the share sheet: nothing is said and no input appears (eng review R4); any other rejection falls through to the input. The input carries `aria-label="Share link"` and joins `panelStops()` right after `#share-copy` (`isStop` drops it while hidden), because the panel's Tab handler `cycleTabStops(panelStops(), e)` prevents native tabbing and a control outside the list is unreachable by keyboard (outside voice C4). The control is `disabled`, never hidden, when `routeFor` refused (S5). No `closePanel()` on click: like the Resources links, the user stays in the menu.

**Events (S3, recommended):** `track("share_copy", { deck_kind: "seeded" | "custom", method: "clipboard" | "share" | "select" })` after a successful copy, share or select, through W1's `track()`; no id, no name, no code, every value under 40 characters (the existing W1 test over all `track()` call sites covers it). `page_location` is unchanged and still hash-free (edge 11).

### Architecture
- One rule (`routeFor`), one writer (`syncRoute`), three write sites, every reader already present (`routeDeck`, `openShare`, the sheet routes). The only new state is `pendingPop`, a boolean with one setter and one consumer.
