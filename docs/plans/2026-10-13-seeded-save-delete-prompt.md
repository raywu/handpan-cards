# Plan-drafting prompt: seeded decks get SAVE / DELETE, not FORK / HIDE

Owner request, 2026-10-13, verbatim:

> Let's remove the fork this deck and hide this deck paradigm for seeded scale. Give seeded deck the same treatment as custom decks: save this deck or delete. This is a simpler model for both the user and our system design. We should give users a way to reset to restore all seeded models - with a warning that all their edits will be gone.

Owner addition, 2026-10-13, verbatim: "I do want a visible edit cue like custom decks do on all the chips."

"Seeded" is the owner's word for the five built-in decks (`const DECKS`). The prompt below is what the planning agent receives, unchanged. Everything after "## Quality rubric" is the coordinator's record and is not part of it.

### The request

Today a seeded deck has a second mode of its own: tapping its already-selected chip opens the scale sheet in builtin mode, where the primary button reads FORK THIS DECK (which mints a `custom:` copy, position 1) and the destructive button reads HIDE THIS DECK (which pushes the id onto the `hidden` array of the `hpfc` blob). A custom deck's selected chip opens the same sheet in Edit mode: SAVE CHANGES and DELETE THIS DECK. The owner wants ONE model: a seeded deck's selected chip opens the sheet in Edit mode exactly as a custom deck's does, with SAVE CHANGES and DELETE THIS DECK, builtin mode goes away, and a new control restores every seeded deck after a warning that the player's edits to them will be gone. Three requirements are binding:

1. **One sheet mode for every deck.** No FORK, no HIDE, no `builtinId`, no third state in `setSheetMode`. Whatever a seeded deck needs under the hood, the player sees SAVE CHANGES and DELETE THIS DECK with the same arm-and-confirm pattern (`delBtn.onclick`, `DEL_IDLE` / `DEL_ARMED`, `delNote`).
2. **A visible edit cue on the chips, the way custom decks have one.** Today `buildChips` adds class `editable` (the `::after` pencil) and the "Edit <name>" accessible name only when the chip is BOTH selected and custom. Extend the cue to seeded decks. The owner's words are "on all the chips"; the plan carries that as decision SD-1 with two readings: (a) the selected chip of ANY deck carries the pencil, seeded included, which is the existing custom convention applied to every deck; (b) every chip carries the pencil whether selected or not. Recommend (a) and say why (row 262 of the earlier work: a pencil on an unselected chip advertises an action that chip does not perform, because only the selected chip opens the sheet). State what each reading does to `tests/app.test.js` "the layout markup exists and a built-in deck is never editable" and `tests/e2e.test.js` "a selected custom chip carries a pencil; no built-in chip ever does" and their mutants (`e_chip_pencil_on_builtins`, `e_chip_aria_uses_full_name`): under either reading both tests are retitled and re-pointed, never deleted, and the mutant `# kills:` headers follow the new titles.
3. **RESET, with a warning.** One control that brings back every seeded deck. It carries the owner's warning in its copy, in substance: your edits to the seeded decks will be gone. Use the house arm-and-confirm pattern (first tap arms and shows the warning, second tap acts, looking away disarms), not `confirm()`.
