# Quality refactor plan (2026-09-30)

Source: three read-only audits run against main at e8f9be8 with the prompt in
"Audit prompt" below — app shell (`index.html` outside generated regions),
engine + tools (`src/engine/`, `tools/`), tests + harness (`tests/`, CI).
Line numbers are at e8f9be8 and will drift; every finding also names a symbol.

## Goal

Cut the cost of changing this repo without changing what it ships: fewer
places to edit per change, fewer stale mutants per change, a faster CI
critical path, and tests that fail for the right reason.

**Done when:** every lane below is merged, `index.html` and the six PDFs are
behaviourally identical to e8f9be8 (same DOM per card, same PDF text and
vector counts), no FLOORS row is lowered, and the longest mutation-gate shard
runs under 6 min in CI (the measure lane C is accepted on).

## Non-goals

- No feature work of any kind.
- No change to deck data, diagram geometry, palettes, fonts, card anatomy,
  label sizes, or any "verified" convention in CLAUDE.md.
- No dead-code removal covered by quality-eval §7 **D3** (hifi `back_card`,
  `Page.arc`, etc. — owner chose to keep them).
- No removal of the `gb` / tone-colour plumbing (CLAUDE.md keeps it on
  purpose) or the `--sep` / `--tone` / `--gb` CSS variables.
- No bulk mutant retirement (backlog-and-refactor §6 **O3**). New mutants only
  for an escape path a lane closes, plus one per new test group. The 5 slow
  hygiene mutants stay.
- No hand edits inside `<!-- engine:* -->` regions or the `const DECKS` line.
- No weakening a test to make a refactor pass. A refactor that needs that is
  not a refactor.

### Merge gates (standing)

1. CI green at a head SHA verified with `gh pr view --json state,headRefOid`
   against the local tip.
2. A fresh `swarm-reviewer` returns PASS or PASS_WITH_NITS at that SHA,
   briefed with the lane's ownership row and non-goals. Reviewer checks out
   with `git checkout -b review-<lane> <sha>`.
3. Bounce cap 2 per lane, one counter for every retry path.
4. `gh pr merge <n> --merge --match-head-commit <sha>`.
5. After merge, any open lane whose branch now **conflicts** rebases; one
   merely behind does not.
6. **Exception — semantic coupling.** Lanes T, B and A all touch the line-ref
   ratchet allowlist's subject matter, and B/A both feed `card_face_v1.json`.
   These can break main without a textual conflict. Before merging any of
   T, B or A while another of them has merged since its CI ran, merge
   current main into the lane branch (no rebase, no force-push), push, and
   take CI at that new head as the evidence.

## Risks

- **Sharding hides a flake.** A per-shard survivor is harder to reproduce.
  Mitigation: the shard report names the mutant and the rerun command; the
  "rerun the failed job at the same SHA first" rule still applies.
- **Refresh tool re-anchors to the wrong place.** Mitigation: refuse on a
  non-unique anchor; `--check` in CI; the mutant must still be killed after
  refresh, which `mutation_check.sh` proves.
- **Engine dedupe changes load order.** `HPE` modules are concatenated in
  region order; a helper moved to `core.js` must be defined before its first
  use. Mitigation: `boot_sim.js` and the file-open e2e boot test.
- **Header fixes change which suites a mutant runs (finding 12).** A mutant
  that was "killed" by a test outside its declared suite can start surviving
  once the header is right. That is a real gap surfacing, not M's regression:
  M lists every such mutant in its PR and either writes the killing test or
  files a queue row; it never reverts the header to hide it.
- **`render()` change (finding 18) touches every card.** Highest-risk item in
  A; do it last in that lane, behind the 96-card invariant checks.
